# 残余风险与未完成事项

以下问题没有被标记为“彻底修复”。

## RISK-001 — 外部通知严格 exactly-once

- 级别：P1
- 现状：通知发布和 River enqueue 有唯一参数约束，数据库日志可追踪，但外部 SMS、Email、Push Provider 没有统一幂等键。
- 风险：Provider 已接收但客户端超时、随后重试时，外部副作用可能重复。
- 建议：引入 Transactional Outbox + recipient/channel 粒度投递表，并要求 Provider 支持 idempotency key。

## RISK-002 — Transactional Outbox 未全面覆盖

- 级别：P1
- 现状：工作流、核心用户事务和 Scheduler 已使用数据库原子边界。
- 风险：通知发布和实时事件仍可能在数据库提交后、消息投递前出现进程中断。
- 建议：把需要跨进程传播的领域事件统一写入 outbox，再由 relay 投递。

## RISK-003 — Refresh history 无归档

- 级别：P2
- 现状：每次旋转都会保留旧 Refresh Hash。
- 风险：长期高活跃系统历史表持续增长。
- 建议：按保留周期归档或分区，但不能在 Session Family 仍有效时删除重放检测所需记录。

## RISK-004 — 可信代理 CIDR 必须部署配置

- 级别：P1（配置风险）
- 现状：默认不信任任何代理头，代码已安全。
- 风险：在 Helm/Ingress 场景留空时，API 会看到代理 IP，登录限流可能按代理聚合；反过来过度宽泛信任私网也可能允许伪造。
- 建议：只配置实际的 Ingress Controller / Load Balancer 出站 CIDR。

## RISK-005 — Helm 不内置基础设施

- 级别：P2
- 现状：Chart 只包含 API 和 Worker。
- 缺失：PostgreSQL、Redis、S3、Ingress、Secret、NetworkPolicy、PDB、备份。
- 建议：由部署平台提供，并在 CI/CD 中做连通性、恢复和故障转移演练。

## RISK-006 — 文件删除补偿

- 级别：P2
- 现状：元数据先软删除，再删除对象。对象删除失败时不会重新暴露文件。
- 风险：对象存储中残留不可见对象，增加成本。
- 建议：增加异步 GC/补偿任务，以 StorageKey 和删除失败记录清理。

## RISK-007 — 旧库缺失文件对象

- 级别：P2（数据质量）
- 现状：9 个 legacy 文件在源上传目录缺失，导入报告已记录跳过。
- 风险：这 9 个历史文件不可提供下载。
- 建议：找回源对象后使用固定 UUID 映射补导，不要生成占位文件。

## RISK-008 — 旧库孤立群组

- 级别：P2（数据质量）
- 现状：1 个群组 owner 不在旧用户集，导入报告已记录跳过。
- 风险：该群组历史不可挂到有效 owner。
- 建议：业务确认 owner 后按固定映射补导。

## RISK-009 — 组织岗位缺失父级

- 级别：P2（数据质量）
- 现状：2 个岗位父级在旧库缺失，按 root 导入。
- 风险：组织结构展示与旧系统可能有层级差异。
- 建议：业务确认原父级，不伪造节点。

## RISK-010 — Scheduler 未做崩溃注入

- 级别：P2
- 现状：关键步骤已进入同一事务，Worker 实际启动正常。
- 缺失：没有在“事务各步骤之间强杀进程”的故障注入测试。
- 建议：在预发布环境加入 Chaos/Failpoint 测试。

## RISK-011 — 权限 epoch 查询成本

- 级别：P2（性能）
- 现状：每次 access 检查读取单例 epoch 行。
- 风险：高 QPS 下增加数据库读取；大量权限变更会竞争单行更新。
- 建议：压测后考虑进程内短缓存，但必须保证 epoch 失效不可越过安全边界。

## RISK-012 — 部分管理资源未做部门级 Data Scope

- 级别：P2
- 现状：用户、文件、公告、聊天、工作流已重点加固。
- 其他：字典、系统配置、部分组织管理仍主要依赖 RBAC 权限。
- 建议：根据业务角色继续逐接口定义资源级范围。

## RISK-013 — WebSocket 心跳要求

- 级别：P2
- 现状：服务端读超时为 90 秒。
- 风险：客户端必须在该窗口内 ping 或发送业务消息。
- 建议：Vue/UniApp 客户端保持现有心跳；否则应由客户端团队确认并调整。

## RISK-014 — Metrics 抓取认证

- 级别：P2（运维）
- 现状：`/metrics` 需要 `audit:read`。
- 风险：未配置认证的 Prometheus scrape 会收到 401。
- 建议：使用只读监控账号和 secret 配置 Bearer Token，或由受控内部代理注入认证。

## RISK-015 — 前端源码不在当前仓库

- 级别：说明
- 现状：当前仓库没有 Vue/UniApp 源目录，只有 Go API 兼容测试。
- 本轮没有修改前端 UI。
- 本轮无法重新执行前端构建，只验证了 API 契约和真实 UI 所需接口行为。
